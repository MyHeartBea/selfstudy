## 一、项目定位：这个项目到底是干什么的

一个**单机（本机）单用户考研错题管理应用**，核心闭环：

```
录入（手动 / 文本 AI / 截图三通道视觉识别）
   ↓
错题库（三种题型 + 真题/模拟题分类 + 知识点标签）
   ↓
复习（今日复习：间隔重复 1/3/7/15/30；自主练习：曲线/错时/随机/真题专项）
   ↓
沉淀（知识点库 + 公式背诵库 + 科目指南 + 统计）
```

- 后端 FastAPI + SQLite（裸 sqlite3，无 ORM），前端 Vue 3 + Element Plus + GSAP + KaTeX。
- 单端口生产模式（前端构建产物由后端挂载），默认只监听 `127.0.0.1:8000`。
- AI 能力（可选）：DeepSeek 文本解析/批改，GLM-4.6V-Flash → Agnes-2.0-Flash → Agnes-2.5-Flash
  三通道视觉轮询识图，全部失败退回本地 Windows OCR + 文本 AI。
- 数据安全：启动自动备份（保留 20 份）、迁移版本门控（app_meta.migration_version=2）、WAL 模式。

## 三、实测验证的问题清单（按优先级）

> 以下问题均已通过**实际运行接口/测试验证**，非仅静态推断。

### P0 —— 正确性 / 稳定性（建议尽快修）

1. **间隔重复 off-by-one**（`review_service.py:173-175`）：答对路径先 `mastery+1` 再取档，
   首次答对 0→1 取 `INTERVALS[1]=3` 天，答对路径实际为 3/7/15/30/30——**`1` 天档永远用不到**，
   与新错题答对后 1 天复现的产品语义不符，记忆曲线间隔偏长。
2. **分页参数缺 page_size 直接 500**（`mistake_service.py:254`、`knowledge_service.py:126`）：
   `GET /api/mistakes?page=1`（不传 page_size）实测返回 500 TypeError，
   被 server_error 吞成「服务器内部错误」。page/page_size 应成对校验或给默认值。
3. **视觉并发成功后未取消其余 future**（`routers/ai.py:137-149`）：首个通道成功或预算耗尽时，
   其余视觉线程仍跑满 30s 超时，浪费 API 配额、占满 3 线程常驻池。应 `future.cancel()`。
4. **前端 `correct_answer` 默认值泄漏**（`mistakeDraft.js:18` 默认 `'A'`）：填空题/解答题
   留空参考答案时提交仍为 `'A'`，详情/列表展示假答案。默认应改为 `''`。
5. **选择题判卷未规范化**（`mistakes.py:119`）：全角 `Ａ` 实测判错，与填空题的
   NFKC 归一化口径不一致；应复用 `normalize_answer`。
6. **`PUT` 空 body 静默清空数据**（`schemas.py:43-47/86-88`）：`PUT /api/knowledge/{id}`
   传 `{}` 实测把 summary 清空；`SubjectProfileUpdate` 同理。应改 PATCH 语义或字段必填。

### P1 —— 体验 / 一致性 / 安全成本

7. **AI 端点无鉴权无限流**（ai.py、mistakes.py:141、knowledge.py:95）：纯本机可接受，
   但若对外暴露，`/ai/ocr`、`/grade`、`/auto-summarize` 可被无限刷，直接消耗 AI 额度。
   建议至少 `API_TOKEN` 环境变量 + 简单限流，README 明示勿对外暴露。
8. **全局异常响应不统一**（main.py:36-50）：未捕获异常透传 FastAPI 默认
   `{"detail": "..."}`；`POST /api/unknown` 实测返回 405 非统一格式；`GET /api` 实测
   返回 SPA 页面而非 404 JSON。建议补 Exception/HTTPException handler。
9. **SubjectGuide 页面 N+1 + 连环错误弹窗**（`SubjectGuide.vue:37-46`）：每个科目串行拉
   profile，新库无档案时 404 会触发全局 toast 连弹 4 条。拦截器应支持「静默」选项。
10. **详情弹窗并发竞态**（`MistakeDetailDialog.vue:46-61`）：快速切换同知识点错题时
    旧响应可能覆盖新数据（CaptureView 已有令牌模式，此处未复用）。
11. **填空复习无手动兜底**（`ReviewView.vue:94-113`）：AI 判分接口失败时填空题流程卡死，
    无「跳过判分手动标记」按钮（选择题/解答题都有绕过路径）。
12. **批量操作计数语义不一致**（`mistake_service.py:403-428`）：pause/resume/source_type
    返回 `len(ids)` 而非实际影响行数，不存在的 id 也报成功。
13. **薄弱知识点统计口径偏颇**（`review_service.py:288-305`）：只取 wrong_count 前 30 行
    错题在 Python 聚合，错题超过 30 道时榜单不完整。

### P2 —— 性能（数据量增长后收益明显）

14. **科目统计 join 放大**（`review_service.py:338-348`）：LEFT JOIN review_records 使每道错题
    的每条复习记录成一行，复习记录多时中间行数膨胀。
15. **练习队列相关子查询**（`review_service.py:104-132`）：每行 2 个 `MAX(reviewed_at)`
    子查询，可改 GROUP BY 预聚合。
16. **标签检索全表扫描**（`mistake_service.py:215/291`、`review_service.py:92`、
    `knowledge.py:108`）：`instr(',tags,', ?)` 无法走索引；规模化后可拆关联表或 FTS5。
17. **导入接口 N+1**（`transfer.py:60-80`）：5000 条导入 = 约 1 万+ 次子查询 + 数千次单条
    INSERT；可预加载科目集合 + executemany。
18. **KaTeX 缓存整表清空**（`markdown.js:26`）：超 500 条整表 clear，热公式也失效；
    建议 LRU 式淘汰。
19. **导出超过 1000 条静默截断**（`useImportExport.js:18-40`）：page_size=1000 不分页翻页。

### P3 —— 一致性 / 移动端 / 可维护性

20. **弹窗固定 px 宽度**（MistakeDetailDialog:180、FormulaView:271/314/329 等）：≤560px
    屏横向溢出，建议 `min(760px, 92vw)`。
21. **路由前缀与分层风格分裂**：reviews/stats/transfer/subjects 用 `/api` 前缀，
    formulas/mistakes/knowledge/ai 用 `/api/<资源>`；knowledge.py:100-121、subjects.py
    在路由层直接写 SQL 绕过 service。
22. **死代码**：`schemas.py` 的 `ApiResponse`（未使用）、`AiSummarizeRequest`（未使用）、
    `database.py` 的 `shutil`、`routers/ai.py` 的 `server_error`、`local_ocr.py` 的
    `Language` 导入。
23. **重复实现**：`_local_day_bounds_utc`（review_service 与 stats_service 各一份）；
    DetailMeta 与 ChoiceAnswer 各自的选项映射；`GET /api` 精确路径处理缺失。
24. **键盘可达性缺口**：MistakeCard 只处理 Enter 不处理 Space；RelatedList/FormulaView
    可点击 div 无 role/tabindex/键盘事件。
25. **迁移逐行 UPDATE**（`database.py:184-197`）：11 个 (表,列) 全表载入内存逐行更新，
    可改为单条 UPDATE CASE。
26. **种子/迁移硬编码 id 耦合**（seed_data.py:66-91、database.py:253-265）：科目与二级科目
    id 1-12 两处硬编码，新增科目易踩 FK。

## 六、总体评价

工程对「单机个人使用」的定位是**健康且超出预期**的：分层清晰（routers→services→database）、
参数化查询到位、迁移门控 + 启动备份、AI 输出加固（_wrap_math/JSON 容错）、前端组件拆分与
composable 收敛、30 个测试 + CI 双 job。未发现 SQL 注入与并发数据竞争类安全问题。

主要短板集中在**三处正确性细节**（间隔排期 off-by-one、分页 500、correct_answer 默认值泄漏）、
**视觉并发资源回收**、以及**统计类查询在数据增长后的性能退化**。按第五节优先级逐项收敛即可，
整体无需架构级返工。
